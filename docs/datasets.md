# Datasets

The department's records were not available, so the study uses two datasets:

1. **UCI Student Performance**: real, public data. It is the main evidence for the model's accuracy and for the hypothesis tests.
2. **Simulated YABATECH-format dataset**: generated by the project's own code with the exact fields in Table 3.1. It is used to run and demonstrate the system.

The simulated dataset must always be described as simulated, never as YABATECH's records. Every number below comes from the files in `reports/tables`, which `python -m ml.prepare_data` rebuilds identically each time.

## 1. UCI Student Performance (real data)

| Item | Detail |
|---|---|
| Source | [UCI Machine Learning Repository, dataset 320](https://archive.ics.uci.edu/dataset/320/student+performance) |
| Original study | Cortez, P. and Silva, A. M. G. (2008). Using data mining to predict secondary school student performance. *Proceedings of the 5th FUBUTEC Conference*, Porto, pp. 5–12 |
| Licence | CC BY 4.0, which allows use with attribution |
| Students | 649 (Portuguese course, the main file); 395 (Mathematics, used only as a robustness check) |
| Setting | Two secondary schools in Portugal: Gabriel Pereira (423 students) and Mousinho da Silveira (226) |
| Files | `backend/data/raw/uci/` (original), `backend/data/processed/uci_por_prepared.csv` (prepared) |

### How its fields map to the study's variables

| UCI field | Study variable | Meaning |
|---|---|---|
| `absences` | Absences | Number of school absences: the attendance indicator |
| `G1` (0–20) | First-period grade, % | The early continuous assessment |
| `G2` (0–20) | Second-period grade, % | A later continuous assessment |
| `failures` | Past failures | Number of past class failures: prior academic history |
| `studytime` | Weekly study time | 1 = under 2 hours, 2 = 2–5, 3 = 5–10, 4 = over 10 |
| `G3` (0–20) | Final grade, % | The outcome, grouped into performance classes |

Grades are multiplied by 5 to read as percentages (a G1 of 11 becomes 55%).

### Performance classes

Classes follow the Portuguese 0–20 scale used by Cortez and Silva: 16–20 Distinction, 14–15 Merit, 10–13 Pass, 0–9 Fail. Their five levels are kept, except that 10–11 and 12–13 are merged into Pass.

| Class | Students | Share |
|---|---|---|
| Distinction | 82 | 12.6% |
| Merit | 112 | 17.3% |
| Pass | 355 | 54.7% |
| Fail | 100 | 15.4% |

### Points to know

- 15 students have a final grade of 0 because they did not sit the final assessment. They are kept and counted as Fail.
- Absences correlate only weakly with the final grade (r = −0.09). Attendance is a weak signal in this dataset, and Chapter 4 should report that honestly.
- The first- and second-period grades correlate strongly with the final grade (r = 0.83 and 0.92). The second-period grade comes late in the year, so the early-warning model uses only the first.
- 382 students appear in both files. The two files are never combined, so no student is counted twice.

## 2. Simulated YABATECH-format dataset

### Why it exists

The system is built around the fields in Table 3.1 and YABATECH's structure: ND1 to HND2, sessions 2020/2021 to 2024/2025, and NBTE grading. No public dataset has those fields, so the project generates one. It lets the system run end to end and be demonstrated with records that look like a department's. Its model results show that the system works; they are not evidence about real YABATECH students.

### Files

| File | Rows | What it is |
|---|---|---|
| `backend/data/simulated/yabatech_simulated_raw.csv` | 2,264 | Raw export, with the record-keeping errors a real export would have |
| `backend/data/processed/yabatech_simulated_clean.csv` | 2,208 | Cleaned records, used for modelling |
| `backend/data/simulated/current_semester_2025_2026.csv` | 237 | First semester of 2025/2026 before exams, the session the system is demonstrated in (1.8). It has no exam score or GPA yet. |
| `backend/data/simulated/demo_student_directory.csv` | 829 | Fictional names and matric numbers for the demo app. Matric numbers start with `SIM/`, so none can be mistaken for a real one. |

### Fields

One row is one student in one semester.

| Field | Meaning |
|---|---|
| `student_code` | Anonymous code, the same for a student in every semester |
| `level` | ND1, ND2, HND1 or HND2 |
| `session`, `semester` | For example 2022/2023, First |
| `attendance_pct` | Average share of lectures attended across the semester's courses, 0–100 |
| `ca_score` | Average CA test score, % of the CA-test maximum |
| `assignment_score` | Average assignment score, %; a missed assignment counts as 0 |
| `exam_score` | Average examination score, %. This is an outcome and is never a model input. |
| `gpa` | Semester GPA on the NBTE 4.00 scale. This is the outcome. |
| `prior_gpa` | GPA of the previous semester. For HND1 first semester it is the final ND CGPA; for ND1 first semester it is blank, because new students have none. |
| `performance_class` | From the semester GPA: Distinction ≥ 3.50, Merit 3.00–3.49, Pass 2.00–2.99, Fail < 2.00 (NBTE cut-offs) |

### How it was generated

All of the logic is in `backend/ml/simulate.py`. In outline:

1. **Cohorts.** About 60–80 ND and 42–58 HND students enter each session from 2019/2020 to 2025/2026. Students entering in 2019/2020 supply the second-year records for 2020/2021. HND entrants start slightly stronger, because they have already passed ND.
2. **Hidden traits.** Each student has an ability and an engagement level, correlated at 0.45. Neither is ever written to a file.
3. **Each semester.** The student's form varies a little from term to term, and there are small level and session effects. Each measure (attendance, CA, assignment, exam) also gets its own shock for the semester, such as exam-period illness or poor preparation.
4. **Each of 8 courses.** The student attends some of 30 lectures, then sits CA tests, submits assignments (or doesn't) and writes the exam. Below 40% attendance there is a 15% chance of missing the exam.
5. **Grading.** Course total = 30% CA tests + 10% assignments + 60% exam. Totals are graded on the NBTE scale (A = 75–100 = 4.00 down to F = 0–39 = 0.00). The semester GPA is the credit-weighted average of the grade points.
6. **Withdrawal.** After a poor semester a student may leave: a 30% chance below GPA 1.00, 10% below 1.50, and 1.5% otherwise.

Effect sizes were set so the relationships have realistic strength, not so that any model would look accurate. For example, attendance correlates with grades at about r = 0.44 in the meta-analysis by [Credé, Roch and Kieszczynka (2010)](https://doi.org/10.3102/0034654310362998); here it correlates 0.53 with semester GPA.

### Record-keeping errors and cleaning (3.5, 3.16)

The raw export deliberately contains errors a real export would have: duplicate entries (1%), labels typed differently ("nd 1", "1st", "2021/22"; 3%), missing attendance (4%), missing assignment (6%), missing CA (1%), withheld results (0.5%), incomplete records (0.5%), and typos such as 83.3 typed as 833. `backend/ml/cleaning.py` applies these rules:

| Step | Records affected | Records left |
|---|---|---|
| Records received | 2,264 | 2,264 |
| Level, semester and session labels standardised | 179 | 2,264 |
| Impossible values blanked (out of range or not a number) | 5 | 2,264 |
| Removed: missing or unrecognised student code, level, semester or session | 0 | 2,264 |
| Duplicate records removed | 27 | 2,237 |
| Removed: no semester GPA, so the outcome is unknown | 12 | 2,225 |
| Removed: two or more of attendance, CA and assignment missing | 17 | 2,208 |

Single gaps that remain are filled during modelling: the median from the training data only, plus a flag marking that the value was missing.

| Variable | Missing after cleaning |
|---|---|
| Attendance | 79 (3.6%) |
| CA score | 25 (1.1%) |
| Assignment score | 111 (5.0%) |
| Previous GPA | 348 (15.8%, mostly ND1 first semester) |

### Limitations

- The relationships in the simulated data come from the generator's assumptions. A model trained on it rediscovers those assumptions, so its accuracy cannot be claimed for real students. That is why the UCI results carry the study's evidence.
- Names in the demo directory are random pairings of common Nigerian first names and surnames. Any match with a real person is coincidence.
